# Design Document: Faberon v0.2.0 (autonomy)

**Status:** current WIP (design review last updated 2026-09-16).
This doc describes what v0.2.0 should ship and is frozen afterwards.

## Goal

One autonomous campaign loop, bounded and observable:

hand-POSTed plan → `run_campaign` workflow loops: the proposer (Pydantic AI agent) edits `train.py` and commits, the job runs on Slurm, the durable poll parses the metric, the judge keeps or discards (keep promotes the commit, discard reverts), and the loop repeats until a stop condition fires. Every step lands in the ledger, streamed over `GET /v0/campaigns/{id}/events` (SSE) and readable as a bounded JSONL snapshot at `GET /v0/campaigns/{id}/events.jsonl`. A human can cancel at any time. A killed control plane resumes mid-campaign exactly once.

Still tested against Karpathy's [autoresearch](https://github.com/karpathy/autoresearch) (5-minute `train.py`, `val_bpb` metric).

## In scope

- `run_campaign` DBOS workflow: propose → run → judge → keep/discard → repeat. One experiment in flight (`max_concurrency=1`).
- Proposer: a Pydantic AI agent with typed tools (read the ledger, read `train.py`, propose an edit plus rationale). Its only write path is a validated replacement of the single target file. The agent sees the full campaign history; the control plane imposes no filter, window, or compaction. The whole conversation (all LLM round trips and tool calls) is one DBOS step, so replay returns the checkpointed proposal without re-calling the LLM.
- Git lineage: each experiment is one commit in the target repo. Keep promotes it (the head moves). Discard reverts `train.py` to the parent commit.
- Sequential checkouts only. No worktrees, no DBOS queue in this release.
- Stop conditions honored: the hard checks run in one place, the top of the loop, in precedence order cancel, then budget, then cap (`max_experiments`, `budget_gpu_hours` from sacct elapsed times). No mid-poll cancel.
- Walltime (pulled forward from the scale work): each plan declares its per-job walltime in minutes (`walltime` plan field, required, passed to Slurm as bare-minute `--time`). An optional deployment-side cap (`FABERON_SLURM_MAX_TIME`, minutes) can only lower it; the effective limit is the smaller of the two. The executor clamps at submit time.
- Cancel: `POST /v0/campaigns/{id}/cancel`, checked at every loop decision boundary.
- Schema additions in the quarantined module: `experiment.proposed` and `campaign.ended` event types (the end event payload carries a `StopReason`, enforced by the event model), `max_experiments` and `walltime` plan fields.
- LLM access: provider-agnostic through `FABERON_MODEL`; v0.2.0 supports local models and OpenRouter. Keys come from the environment, never the repo or the ledger. The operational path (egress verification, local serving stack) is open, see roadmap.md.
- Cluster runbook updated for the loop.

## Out of scope

Planned for later releases: see [roadmap.md](roadmap.md). Speculative ideas: see [future.md](future.md).

- Console, drafter, ideas, approvals: v0.3.0.
- Parallel experiments (worktrees, DBOS queue): v0.4.0.
- Judgment quality (confidence measure, non-regression, constraint gates) and the notes file: v0.5.0.

## v0.2.0 stand-ins

- **Judgment.** Same fixed rule as v0.1.0, but the comparison is against the current head: an edit is kept if its metric beats the best metric so far (not the original baseline every time). The plan baseline seeds the first comparison. No confidence measure. Failed or cancelled jobs, and unparseable metrics, are discards; the judged event payload records why, and the head does not advance. A submit exception halts the campaign: DBOS resumes on control-plane restart, and the human decides. Failed runs consume an experiment slot, and their sacct elapsed counts against budget. A terminal job without a usable sacct elapsed raises rather than silently counting as zero.
- **Stop conditions.** Only hard caps are enforced. Free-text stop conditions are recorded and visible, not enforced.
- **Cancel.** Takes effect at the next decision boundary. An in-flight job finishes, bounded by its walltime. Immediate `scancel` arrives with the approval-gate work.
- **Budget accounting.** GPU-hours are computed from sacct elapsed times times requested GPUs. No live metering.

## Exit test

Start a campaign on autoresearch with a cap of 6 experiments. Walk away. Come back to:

- 6 judged experiments in the ledger, each with proposal, completion, and judgment events.
- One commit per experiment in the target repo, and the working tree at the best kept one.
- `sacct` shows no job ran twice.
- The loop stopped on the cap, with a campaign-end event saying so.

Durability extension: kill the control plane between experiments and mid-experiment. On restart, the in-flight job is not resubmitted and the loop finishes the campaign exactly once.
